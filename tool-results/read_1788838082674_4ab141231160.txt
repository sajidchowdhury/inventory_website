    37→## 1. Project Vision & Goals
    38→
    39→### 1.1 Vision
    40→A **premium, clean, mobile-friendly** Laravel web application that replaces the manual Excel workbook ("Investors Report 2026 New.xlsx" → "July, 2026 For Sajid" sheet) for managing a Mudaraba profit-sharing pool. The system must feel as fast and tactile as Excel for the M/Y's daily workflow, while enforcing data integrity, audit trails, and proper business logic that the spreadsheet cannot guarantee.
    41→
    42→### 1.2 Goals
    43→
    44→| # | Goal | Success Metric |
    45→|---|------|----------------|
    46→| G1 | Accurate replication of the Excel 8-phase calculation engine | Monthly reconciliation matches Excel to ±BDT 1.00 |
    47→| G2 | Premium UI that an Excel power-user enjoys | First-time user can complete a monthly run without training |
    48→| G3 | Mobile-friendly responsive design | 100% of workflows usable on a 375px-wide phone |
    49→| G4 | Proper relational database with enforced integrity | Zero orphaned transactions; all FKs enforced |
    50→| G5 | Audit-grade transaction history | Every financial mutation is traceable to user + timestamp |
    51→| G6 | Add the missing Retained Earnings mechanism | 71/29 split of BDT 200K automated monthly |
    52→| G7 | Role-based access control | Operators see only permitted modules |
    53→
    54→### 1.3 Non-Goals (this project)
    55→- MuRabaha parallel system (separate project later)
    56→- Public-facing investor portal (operator-only for now)
    57→- Real-time currency conversion / multi-currency
    58→- Automated bank integration

    71→## 2. Technology Stack Decisions
    72→
    73→### 2.1 Backend
    74→| Component | Choice | Rationale |
    75→|-----------|--------|-----------|
    76→| Framework | **Laravel 11** (latest LTS) | Mature, excellent ORM, queue, auth, validation |
    77→| Language | **PHP 8.3+** | Typed properties, enums, readonly — fits financial domain |
    78→| Database | **PostgreSQL 16** (primary) | True `DECIMAL` arithmetic, `CHECK` constraints, window functions, partial indexes — essential for finance. MySQL 8 is an acceptable fallback. |
    79→| Cache | Redis | Session, cache, queue |
    80→| Queue | Laravel Queue (Redis driver) | Async PDF generation, bulk imports |
    81→| Search | Laravel Scout + database driver (for now) | Investor/sector quick search |
    82→
    83→### 2.2 Frontend
    84→| Component | Choice | Rationale |
    85→|-----------|--------|-----------|
    86→| Rendering | **Inertia.js + React 18** | SPA feel without building a separate API; Laravel routes serve React pages directly |
    87→| Styling | **Tailwind CSS 4** | Utility-first, responsive, fast iteration |
    88→| Components | **shadcn/ui** (New York style) | Premium, accessible, customizable, not a "template look" |
    89→| Icons | **Lucide React** | Consistent, modern, lightweight |
    90→| Charts | **Recharts** | React-native, responsive, composable |
    91→| Tables | **TanStack Table v8** | Headless, supports Excel-like inline editing, virtualization for 150+ investor grids |
    92→| Forms | **React Hook Form + Zod** | Performant, schema-validated |
    93→| Notifications | **Sonner** (toasts) | Premium toast UX |
    94→| Animations | **Framer Motion** | Subtle micro-interactions |
    95→
    96→> **Why not Livewire/Filament?** Filament is excellent for admin CRUD but produces a recognisable "admin panel" aesthetic. The M/Y currently lives in Excel — we need a bespoke, premium financial UI, not a generic admin skin. Inertia + React + shadcn gives full creative control.

   112→## 3. UI/UX Design Principles
   113→
   114→### 3.1 Design Philosophy
   115→> *"Make the M/Y forget Excel — but feel at home."*
   116→
   117→The system must combine **spreadsheet ergonomics** (fast bulk entry, inline editing, keyboard navigation, live formula previews) with **premium SaaS aesthetics** (clean whitespace, refined typography, subtle motion, considered color).
   118→
   119→### 3.2 Visual Design System
   120→
   121→**Color palette** (light + dark mode, NO indigo/blue per house style):
   122→
   123→| Token | Light | Dark | Usage |
   124→|-------|-------|------|-------|
   125→| `background` | `#FFFFFF` | `#0A0A0B` | App canvas |
   126→| `surface` | `#FAFAFA` | `#141416` | Cards, panels |
   127→| `surface-2` | `#F4F4F5` | `#1C1C1F` | Nested sections, table headers |
   128→| `border` | `#E4E4E7` | `#27272A` | Dividers |
   129→| `foreground` | `#18181B` | `#FAFAFA` | Primary text |
   130→| `muted` | `#71717A` | `#A1A1AA` | Secondary text |
   131→| `primary` | **Emerald `#10B981`** | same | Action, positive (growth/profit) |
   132→| `accent` | **Amber `#F59E0B`** | same | Highlight, retained earnings |
   133→| `success` | `#22C55E` | same | Receivable to M/Y |
   134→| `danger` | `#EF4444` | same | Payable / over-paid / loss |
   135→| `warning` | `#F59E0B` | same | Variance flag |
   136→| `info` | `#06B6D4` | same | Neutral info |
   137→
   138→> Emerald as primary signals growth & Islamic-finance green-adjacent connotation without being literal. Amber accents tie to retained-earnings gold.
   139→
   140→**Typography**:
   141→- Sans: **Inter** (UI, tables, forms)
   142→- Mono: **JetBrains Mono** (numbers, monetary values, cell refs) — monospace numbers align in columns like Excel
   143→- Display: **Inter Tight** (headings, dashboard KPIs)
   144→
   145→**Spacing & radius**: 4px grid; `rounded-xl` (12px) cards; `rounded-lg` (8px) inputs; `rounded-md` (6px) buttons.
   146→
   147→**Shadows**: Layered, soft — `shadow-sm` default, `shadow-md` on hover, `shadow-lg` on modals.
   148→
   149→### 3.3 Interaction Principles
   150→
   151→| Principle | Implementation |
   152→|-----------|---------------|
   153→| **Spreadsheet-grade data entry** | TanStack Table with inline-editable cells; Tab/Enter navigation; paste from Excel; "fill down" |
   154→| **Live calculation preview** | As M/Y types sector actuals, investor profit columns recompute in real-time before save (mirrors Excel formula feel) |
   155→| **Color-coded financials** | Over-payment (receivable) = green tint; under-payment (payable) = red tint; zero = neutral |
   156→| **Month switcher always visible** | Top-bar persistent month selector — jump between months instantly |
   157→| **Sticky summary row** | Totals (X2, Y2, Z2, M/Y profit) pinned at top of investor grid, updating live |
   158→| **Keyboard-first** | `Cmd/Ctrl+K` command palette; `J/K` to navigate tables; `E` to edit; `S` to save |
   159→| **Subtle motion** | Framer Motion: 150ms ease-out for hovers; 200ms for panels; number count-up animations on KPIs |
   160→| **Empty states** | Every empty view has an illustration + CTA (never blank) |
   161→| **Toast feedback** | Every save/update/delete confirms with Sonner toast (success/danger variants) |
   162→| **Optimistic + skeleton loading** | Skeleton rows on fetch; optimistic update on inline edit |

   199→## 4. Database Design
   200→
   201→### 4.1 Design Improvements over the PHP Version
   202→
   203→| Issue in PHP version | Fix in Laravel version |
   204→|----------------------|------------------------|
   205→| No foreign keys (only logical) | All FKs enforced at DB level |
   206→| Mixed `float(20,2)` / `double` / `decimal` | Uniform `DECIMAL(20,2)` everywhere money |
   207→| `advance_paid` column actually stored the *difference* | Renamed `advance_difference`; separate `primary_profit_share` column |
   208→| No Retained Earnings tables | New `retained_earnings` + `retained_earnings_distributions` |
   209→| No audit trail | `audit_logs` table + model observations |
   210→| No soft deletes | Soft deletes on financial records (never hard-delete) |
   211→| `created_by` only on some tables | Universal `created_by`, `updated_by`, `deleted_by` |
   212→| Month stored as `varchar(7)` `'2026-07'` | Native `DATE` (1st of month) + generated `YYYY-MM` column |
   213→| No transaction batching | `transaction_batch` UUID for atomic month-reconcile ops |

   623→## 5. Business Logic Specification
   624→
   625→### 5.1 The 8-Phase Calculation Engine (canonical, from DOCX)
   626→
   627→```
   628→INPUT: 17 sectors × (estimated_profit, actual_profit) for month M
   629→       151 investors × (investment balance, deed_ratio) as of month M
   630→
   631→PHASE 1 — Totals
   632→  Z2 = Σ sector.estimated_profit         (total primary / advance pool)
   633→  X2 = Σ sector.actual_profit            (total realized)
   634→  Y2 = Z2 − X2                           (sector advance difference)
   635→  D181 = Σ investor.investment           (total mudaraba pool)
   636→
   637→PHASE 2 — Per-investor ratio & primary share
   638→  FOR each investor i:
   639→    ratio[i]      = investment[i] / D181
   640→    primary[i]    = ratio[i] × Z2         (paid as advance, start of month)
   641→    actual_full[i] = ratio[i] × X2       (their 100% entitlement)
   642→
   643→PHASE 3 — Tier application
   644→  actual_due[i] = actual_full[i] × deed_ratio[i] / 100
   645→  (deed_ratio ∈ {100, 80, 60})
   646→
   647→PHASE 4 — Advance difference (receivable/payable)
   648→  advance_diff[i] = primary[i] − actual_due[i]
   649→    positive → investor was over-paid, owes M/Y
   650→    negative → investor under-paid, M/Y owes them
   651→
   652→PHASE 5 — Retained earnings distribution (NEW vs PHP version)
   653→  RE_total = 200,000      (configurable per month)
   654→  RE_investors = RE_total × 71%  = 142,000
   655→  RE_my        = RE_total × 29%  = 58,000
   656→  retained_credit[i] = RE_investors × ratio[i]
   657→
   658→PHASE 6 — Net settlement
   659→  net[i] = advance_diff[i] − retained_credit[i]
   660→    positive → investor owes M/Y (after retained credit)
   661→    negative → M/Y owes investor
   662→
   663→PHASE 7 — Aggregates
   664→  AH182 = Σ advance_diff[i]                 (total investor over-payment)
   665→  AG182 = Σ actual_due[i]                  (total investor profit)
   666→  AJ182 = Σ retained_credit[i]             (total investor retained credit)
   667→
   668→PHASE 8 — M/Y profit
   669→  my_profit = AH182 − Y2                   (Excel AG184)
   670→            = (Z2 − AG182) − (Z2 − X2)
   671→            = X2 − AG182                    (algebraically identical)
   672→  my_ratio  = my_profit / X2 × 100         (target ≈ 29.13%)
   673→```
   674→
   675→### 5.2 Month Reconciliation Flow
   676→
   677→```
   678→1. M/Y opens month M (status = 'draft')
   679→2. Enters estimated sector profits → Z column (start of month)
   680→3. System computes primary_profit_share for all active investors → distributed as advance
   681→4. Month elapses...
   682→5. M/Y enters actual sector profits → X column (end of month)
   683→6. System reconciles:
   684→   a. Computes actual_due, advance_diff, retained_credit, net per investor
   685→   b. Updates investor_profit_due_ledger (+/- advance_diff)
   686→   c. Updates investor_profit_monthly_due
   687→   d. Updates sector_profit_due_ledger (Y2 differences)
   688→   e. Updates director_due_ledger (my_profit)
   689→   f. Writes monthly_profit_summary
   690→   g. Status → 'finalized'
   691→7. Lock month (status = 'locked') — no further edits without admin override
   692→```
   693→
   694→### 5.3 Due-Ledger Rollback-on-Edit Pattern (preserved from PHP)
   695→
   696→When re-saving a finalized month, the system must NOT double-count. The pattern:
   697→
   698→```
   699→FOR each investor i with prior saved values:
   700→  old_advance_diff = stored advance_diff
   701→  new_advance_diff = recomputed advance_diff
   702→  delta = new_advance_diff − old_advance_diff
   703→  investor_profit_monthly_due[i][M] += delta
   704→  investor_profit_due_ledger[i]     += delta
   705→```
   706→
   707→This is implemented as a DB transaction wrapped in a `batch_uuid` for atomicity.
   708→
   709→### 5.4 Investment Balance Computation
   710→
   711→```
   712→investment_till_month(investor, M) =
   713→  Σ (add amounts) − Σ (withdraw amounts)
   714→  WHERE transaction_month <= M
   715→```
   716→
   717→Stored in `investor_due_ledger` as a running balance, updated on each `investment_transactions` insert.

  1086→## 9. Risk Register & Mitigation
  1087→
  1088→| # | Risk | Impact | Mitigation |
  1089→|---|------|--------|-----------|
  1090→| R1 | Floating-point drift in profit calcs | Pennies off across 151 investors | Use `DECIMAL(20,2)` everywhere; round only at display layer |
  1091→| R2 | Double-counting on month re-save | Ledger corruption | Rollback-on-edit pattern (preserved from PHP) + DB transactions + `batch_uuid` |
  1092→| R3 | Excel user rejects new UI | Adoption failure | Build the "For Sajid" view to mirror Excel layout; offer Excel export |
  1093→| R4 | Retained earnings logic wrong | M/Y profit mismatch | Parity test asserts AG184 = 476,220.07 for July 2026 |
  1094→| R5 | Performance on 151-row grid | Sluggish UI | TanStack Table virtualization; defer non-visible rows |
  1095→| R6 | Permission bypass via direct URL | Unauthorized access | Route-level middleware + policy classes on every financial route |
  1096→| R7 | Audit log grows unbounded | DB bloat | Partition `audit_logs` by month; archive > 2 years |
  1097→| R8 | Concurrent month edits | Race condition | Row-level lock on `monthly_profit_summary` during reconcile |
  1098→| R9 | Postgres vs MySQL divergence | Migration issues | Stick to ANSI SQL; avoid Postgres-only JSONB in hot paths |
  1099→| R10 | Dark mode contrast issues | Readability | Test all monetary cells in both modes; WCAG AA contrast ≥ 4.5:1 |

  1127→## 11. Convention & Naming Standards
  1128→
  1129→### 11.1 Database
  1130→- Tables: `snake_case`, plural (`investors`, `monthly_sector_profit`)
  1131→- Columns: `snake_case`, `id` as BIGSERIAL PK
  1132→- Foreign keys: `{entity}_id` (`investor_id`, `sector_id`)
  1133→- Timestamps: `created_at`, `updated_at`, `deleted_at` (TIMESTAMPTZ)
  1134→- Money: `DECIMAL(20,2)` — never FLOAT/DOUBLE
  1135→- Months: stored as `DATE` (1st of month), displayed as `'YYYY-MM'`
  1136→- Booleans: native `BOOLEAN`
  1137→
  1138→### 11.2 Laravel / PHP
  1139→- Models: Singular StudlyCase (`Investor`, `MonthlySectorProfit`)
  1140→- Controllers: Resource controllers (`InvestorController`, `SectorProfitController`)
  1141→- Services: `*Service` suffix (`ProfitCalculatorService`)
  1142→- Form Requests: `*Request` suffix (`StoreInvestorRequest`)
  1143→- Policies: `*Policy` (`InvestorPolicy`)
  1144→- Enums: PHP 8.1 enums for types (`InvestmentType::Add`, `MonthStatus::Finalized`)
  1145→
  1146→### 11.3 React / TypeScript
  1147→- Components: PascalCase (`InvestorProfitGrid.tsx`)
  1148→- Hooks: `use*` prefix (`useMonthReconciliation`)
  1149→- Pages: route-segment files under `resources/js/pages/`
  1150→- API types: Zod schemas → inferred TS types
  1151→
  1152→### 11.4 Git
  1153→- Branches: `feature/phase-4-investor-profit-grid`, `fix/retained-earnings-rounding`
  1154→- Commits: Conventional Commits (`feat:`, `fix:`, `chore:`, `test:`, `docs:`)
  1155→- PRs: squash-merge to `main`
